# Supabase Catalog Backups

Weekly snapshots of the MytheAi Supabase catalog. Generated by `.github/workflows/supabase-backup.yml` every Sunday 03:00 UTC.

## Structure

```
backups/
├── 2026-10-11/
│   ├── MANIFEST.json       # Backup metadata (date, tables, generator)
│   ├── tools.json          # All tool records
│   ├── tasks.json          # All /tasks/[slug] records
│   ├── comparisons.json    # All comparison enrichment records
│   └── tool_reviews.json   # Approved user reviews only (PII stripped)
├── 2026-10-18/
...
```

## What is NOT backed up here

- **newsletter_subscribers** — contains PII (emails). Rely on Supabase native backups + Resend audience as source of truth.
- **Blog MDX files** — already git-tracked in `web/content/blog/`.
- **Top10 lists + categories** — already git-tracked in `src/data/top10.ts`.

## Restore procedure (disaster recovery)

If the Supabase project is deleted entirely:

1. **Create new Supabase project** at https://supabase.com/dashboard
2. **Apply schema** by running `web/schema/initial.sql` + any migrations in `web/*-s*.sql` chronologically.
3. **Restore data** from latest backup folder:
   ```bash
   cd web
   node scripts/restore-from-backup.mjs backups/<latest-date>/
   ```
   (Script does bulk INSERT with ON CONFLICT DO NOTHING per table.)
4. **Update env vars** at Netlify + local `.env.local` with new project URL + keys.
5. **Trigger Netlify rebuild** to pick up new Supabase connection.

## Retention policy

Keep **last 12 weekly backups** (3 months rolling window). Older backups can be deleted manually or via automated prune (future enhancement).

To delete old backups:
```bash
cd backups/
ls -1d 2026-* | sort | head -n -12 | xargs rm -rf
git commit -am "Prune old Supabase backups (keep last 12 weeks)"
git push
```

## Verifying a backup

```bash
cd backups/<date>/
cat MANIFEST.json                                      # Check metadata
node -e "console.log(JSON.parse(require('fs').readFileSync('tools.json')).length)"  # Row count
```
